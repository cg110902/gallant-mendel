# M5.1 Candidate Claims 与 Evidence Binding 补充冻结决策
## Conservative Extraction v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M4 总验收 PASS

## 1. 评估结论与首个切片

M5.1 只实现保守、确定性的候选抽取与正文证据绑定。输入必须是 human-approved、hash 未变化的 `prose.md` 与冻结 ContextPack；输出仅写入对应 Run。候选产物不进入 EventLog/SQLite，不代表事实成立。

首版不使用模型进行开放语义推断。它完成两类可重放抽取：

1. 对 ContextPack 中已注册对象的 canonical name、alias 和 object ID 做精确实体提及定位；
2. 解析正文中的显式隐藏注解 `<!-- novel:claim {...} -->`，生成 candidate claim 与 candidate fact assertion delta。

这种设计优先消除“模型猜到但无证据”的风险。普通自然语言未被抽成 claim 不代表不存在事实；报告必须标记 `semantic_completeness=false`。

## 2. Claim 注解协议

注解 JSON 只允许：

```json
{"subject_id":"char_lin_yun","predicate":"status","value":"exposed"}
```

- `subject_id` 必须是 ContextPack 已注册对象；
- `predicate` 必须为小写结构化标识；
- `value` 必须是有限 JSON 值，拒绝 NaN、重复键和过深/过大的值；
- 每条 claim ID、delta ID、evidence ID 由 canonical 内容与 prose hash 派生；
- 重复语义 claim 保留各自证据，但 delta 按 claim 独立，不进行权威合并。

## 3. Evidence Binding

正文位置采用 Unicode code-point 的半开区间 `[start_char,end_char)`；证据保存 exact quote、quote hash、prose hash 和 `prose.md` 相对路径。发布前必须反向切片验证 quote 完全一致。任何越界、hash 不符或正文变化均以 stale/integrity 错误停止。

## 4. 状态与产物

```text
extraction_ready → extracting → extracted
```

输出：

```text
candidate-claims.json
candidate-state-delta.json
evidence.json
extraction-report.json
```

重复执行在相同输入下按 bytes 幂等；同路径不同内容为完整性冲突。失败保留已存在证据但不得伪装为 `extracted`。

## 5. CLI 与安全边界

```bash
python studio.py extract (--book ID | --path PATH) --run run_<hash> [--json]
```

Extractor 只读 ContextPack、批准记录与 prose，只写 `runs/<run_id>/`。不得读取未来章节、调用 provider、执行 shell、修改 Writer attempt、EventLog、SQLite、compiled 或 chapters。

## 6. 明确排除

不做开放语义模型抽取、关系/知识/义务生命周期判定、Intent/Reality reconcile、硬不变量审计、自动批准、章节发布或权威提交。M5.2 才评估 candidate delta 的确定性 reconcile 与硬闸门前置分类。
