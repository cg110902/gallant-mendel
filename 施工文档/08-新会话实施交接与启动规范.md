# 新会话实施交接与启动规范
## Session-independent Bootstrap v1.0

> 本文件解决一个现实问题：新的 IDE/Agent 会话不会继承历史聊天记忆，因此项目必须通过仓库文件自解释、可恢复、可继续施工。

---

## 1. 这份文件是什么

这是新会话进入项目后的启动合同，不是架构宣传材料，也不是产品说明。

新会话只要读取以下文件，就必须能够知道：

- 项目已经完成什么；
- 哪些内容已经冻结；
- 代码应该写在哪里；
- 当前应该执行哪个里程碑；
- 什么不能提前实现；
- 如何证明本次施工完成。

仓库级入口是：

```text
/home/user/novel-pipeline/AGENTS.md
```

实际工程根目录是：

```text
/home/user/novel-pipeline/v2/
```

施工文档根目录是：

```text
/home/user/novel-pipeline/施工文档/
```

## 4. 施工根目录和路径规则

所有工程动作都从 `v2/` 执行：

```bash
cd /home/user/novel-pipeline/v2
```

从这里执行：

```bash
python studio.py ...
python -m unittest discover -s tests -v
```

必须遵守：

| 内容 | 路径 |
|---|---|
| CLI | `v2/studio.py` |
| 源代码 | `v2/novel_kernel/`、`v2/novel_runtime/` 等 |
| 测试 | `v2/tests/` |
| Schema | `v2/schemas/` |
| 脚本 | `v2/scripts/` |
| 运行数据 | `v2/workspace/<book_id>/` |
| 施工状态 | `v2/施工状态/` |
| 验证证据 | `v2/verification/<milestone>/` |
| 设计文档 | `施工文档/`，只读参考，除非发生正式变更 |

不要在仓库根目录创建第二份 `studio.py`，不要创建第二套 `events.jsonl` 或 `state.db`。

## 6. 新会话的执行方式

开始时先检查环境，不要凭记忆假设：

```bash
pwd
python --version
find . -maxdepth 2 -type f | sort
```

如果 Python 低于 3.12，停止实现并报告环境问题。

如果已有未完成改动：

1. 先读 `施工状态/当前状态.md`；
2. 查看 `git diff` 或文件修改时间；
3. 运行已有测试；
4. 不覆盖未知改动；
5. 将恢复动作记入状态文件。

如果没有未完成改动：

1. 创建或更新 `施工状态/当前状态.md`；
2. 按 `09-M0精确施工与验收附录.md` 实现；
3. 每完成一个小项就运行测试；
4. 只在 M0 通过后进入下一阶段。

## 7. 进度文件规范

`v2/施工状态/当前状态.md` 是会话之间的交接点，至少包含：

```markdown
# 当前施工状态

- 当前里程碑：M0
- 当前子任务：...
- 状态：未开始 / 进行中 / 阻塞 / 已完成
- 最后更新时间：...
- 最后一次命令：...
- 最后一次退出码：...
- 已完成文件：...
- 已通过测试：...
- 已知失败：...
- 下一步唯一动作：...
- 是否发生协议变更：否
```

它是进度记录，不是权威业务状态；不能用它替代事件日志。

---

## 8. 施工完成回复模板

新会话完成一项任务时，必须按以下结构报告：

```text
本次完成：M0.x / ...

改动文件：
- ...

执行命令：
- 命令：...
- 退出码：...
- 结果：...

验收证据：
- ...

未完成或已知限制：
- ...

下一步唯一允许动作：
- ...

架构/协议变更：无；或列出变更记录路径
```

禁止使用“应该没问题”“看起来完成”“模型判断已完成”等无证据表述。

---

## 9. 会话结束前的最小交接

如果本次会话没有完成当前里程碑，必须：

1. 更新 `v2/施工状态/当前状态.md`；
2. 保存当前测试命令和退出码；
3. 说明失败原因；
4. 标出下一步唯一动作；
5. 不留下只存在于聊天窗口的关键决定。

这样下一会话不需要知道本次聊天内容，也能继续施工。
