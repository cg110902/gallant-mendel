# M6.8 并发冲突与资源保护补充冻结决策

- 状态：已接受

## 1. 评估结论

M6.7 只证明单 writer 顺序恢复。M6.8 验证同一本书 EventLog 的两类竞争：锁被占用时的有界失败，以及两个候选从同一 parent 同时追加时的 lost-update 防护。本阶段不扩大到跨主机、分布式锁或多书吞吐。

## 2. 冻结语义

- EventLog append 前必须取得独占 advisory file lock；
- 超过 lock timeout 必须失败为 `RESOURCE_GUARD`（exit 7），且 authority bytes 不变；
- 两个候选从同一 parent 竞争时只能有一个 winner；
- loser 必须以 parent conflict / exit 7 明确失败；
- 禁止自动 reparent、自动重排、last-write-wins 或静默覆盖；
- winner 后 EventLog 必须可 verify，projection 必须追平 winner head。

`ParentConflictError` 与 `ResourceGuardError` 固定 `exit_code=7`。Chapter commit 在 append 窗口遇到这两类错误时转换为 `ProductionResourceGuardError`，CLI 因此返回 7，而不是把并发冲突误报为完整性损坏 6。

## 3. 可执行场景

1. 一个线程持有真实 EventLog lock，第二个 writer 使用 50ms timeout；预期 exit 7、0 authority mutation。
2. 两线程通过 barrier 同时追加不同 event ID、相同 parent；预期 1 winner、1 parent conflict、最终仅新增一个 event。
3. ChapterCommitter append 注入 parent race；预期状态停在 `commit_prepared`、无 chapter 发布、上抛 exit 7 类错误。

## 4. 诚实边界

本阶段只覆盖单进程线程竞争下，由操作系统 file lock 和锁内 head 复核提供的单书写保护。它不证明：

- 网络文件系统锁语义；
- 多主机或分布式 writer；
- 公平性、饥饿避免或吞吐；
- SQLite 多写性能；
- 真实模型并发调度。

M6.5 challenge FN=9 与 warning thresholds 不变。通过后下一步应先评估 M6 总回归与退出条件，而非直接宣称生产可靠。
