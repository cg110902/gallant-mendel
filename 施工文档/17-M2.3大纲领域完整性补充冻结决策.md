# M2.3 大纲领域完整性补充冻结决策
## Outline Domain Completeness v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M2.1、M2.2 已通过
- 影响范围：Character、Faction、Place、Item、Thread、Obligation、Arc、Chapter、Beat 的 hard-failure 完整性

## 1. 阶段边界

M2.3 在布局和语义引用通过后，检查 `07-大纲规格与编译规范.md` 已明确要求的领域字段是否可执行。校验只读，不生成 `compiled/`、production manifest、初始事件或投影。

本阶段不尝试把文学质量完全形式化；不检查 prose 优劣、主题深度、转折是否精彩，也不让 Agent 自动补字段。

## 2. 共同规则

- 记录必须是对象；未知字段暂不拒绝，以允许 Outline v1 向后兼容增加说明字段；
- 必填文本必须为去除空白后非空的字符串；
- 必填集合必须非空且不包含空值；
- 章节号是正整数；权重是 `0..1` 且 bool 不算数字；
- 所有窗口是两个正整数且下界不大于上界；
- 所有诊断按 `code → path → message` 排序；
- domain hard failure 返回退出码 `2`。

## 3. Character

必需：`id`、`name`、`role`、非空 `initial_state`、非空 `motives`、非空 `constraints`、非空 `arc_refs`，以及 `capabilities` 或 `resources` 至少一个非空。缺少能力/资源边界使用 `UNBOUNDED_CHARACTER`。

## 4. Faction / Place / Item

Faction 必需：`id`、`name`、`goal`、非空 `resources`、`hierarchy`、`external_relations`、`internal_conflict`、`known_information_boundary`。

Place 必需：`id`、`name`、`location`、`accessibility`、非空 `environment_constraints`、`faction`/`faction_id`/`owner_faction` 之一、非空 `allowed_actions`、正整数 `first_appearance_chapter`。

Item 必需：`id`、`name`、`current_holder`/`holder`/`owner` 之一、`source`、`capabilities` 或 `limitations` 至少一个非空、非空 `transfer_rules`、布尔值 `foreshadowing_carrier`。

## 5. Thread

必需：`id`、`kind`、`owner`、`start_condition`、`progress_metric`、非空 `turning_points`、`resolution_condition`、`forbidden_resolution`。每个 turning point 必须有 `id`、正整数 `target_chapter`、`action`、`irreversible_change`。

## 6. Obligation

必需：`id`、`kind`、`source_thread`、正整数 `planted_chapter`、有效 `expected_window`、`0..1` 的 `weight`、非空 `allowed_resolution`、`reader_visibility`、非空 `character_visibility`、`evidence_requirement`。

`allowed_resolution` 只允许 `fulfilled | subverted | deferred | retired`。`evidence_requirement.min_clues` 为正整数，`payoff_requires` 为非空 event 引用数组。缺失解决方式使用 `OBLIGATION_WITHOUT_RESOLUTION`。

## 7. Arc

必需：`id`、`volume`、有效 `range`、`entry_state`、`exit_state`、`core_question`、非空 `required_turns`。`obligations_created` 与 `obligations_resolved` 必须为数组，可为空。

## 8. Chapter / Beat

Chapter 必需：`id`、`volume`、`arc`、`purpose`、`pov`、`location`、带 start/end 的 `time`、`intent` 和非空 `beats`。

Intent 必需：非空 `required_events`、非空 `required_changes`、`required_hook`、`forbidden` 数组。缺 purpose 使用 `CHAPTER_WITHOUT_PURPOSE`；缺 hook 使用 `CHAPTER_WITHOUT_HOOK`。

Beat 必需：`id`、`kind`、有效正整数 `target_words` 窗口、`complexity`。

## 9. 诊断与报告

新增诊断码：

```text
DOMAIN_SCHEMA_ERROR
UNBOUNDED_CHARACTER
OBLIGATION_WITHOUT_RESOLUTION
CHAPTER_WITHOUT_PURPOSE
CHAPTER_WITHOUT_HOOK
```

成功报告新增 `outline.domain.v1` summary，至少包含各类型记录数、turning point 数和 beat 数。失败不得留下任何部分编译产物。

## 10. 后续边界

M2.4 才评估确定性 compiled 中间产物、compile report 与原子发布协议。M2.3 不生成事件，不改变 manifest status。
