# ADR-0013：Python 最低版本调整

- 状态：已接受
- 日期：2026-09-29
- 决策者：项目所有者授权
- 影响范围：M0–M8 基础运行环境

## 背景

原 ADR-0001 将 Python 3.12 设为最低版本。实际施工环境为 Debian 12，稳定提供 Python 3.11.2；当前沙箱无法连接外部软件源，也没有可用的 Python 3.12+ 离线解释器。M0 所冻结的标准库能力（`argparse`、`dataclasses`、`datetime`、`hashlib`、`json`、`pathlib`、`sqlite3`、`unittest`）均由 Python 3.11 提供，现有协议没有依赖 Python 3.12 独占语义。

## 决策

1. 将核心最低运行版本从 Python 3.12 调整为 **Python 3.11**。
2. Python 3.11 是兼容下限，不是锁定版本；持续支持更新的 Python 3.x。
3. 核心路径仍保持零第三方依赖。
4. 不得使用未声明降级策略的 Python 3.12+ 独占语法或标准库 API。
5. `doctor` 在 Python 低于 3.11 时返回退出码 `5`。
6. 后续 CI 建立后，最低版本测试必须包含 Python 3.11。

## 理由

- 解除与产品能力无关的环境阻塞。
- 不改变事件、状态、目录、退出码或权威层级协议。
- 扩大本地 IDE 和 Linux 稳定发行版的可运行范围。
- 相比加入隐藏跳过开关，明确调整合同更可审计。

## 后果

- M0 版本输出中的 `python_min` 为 `3.11`。
- 所有施工文档中的 Python 最低版本同步为 3.11。
- 如果未来功能确实需要更高版本，必须以新的 ADR、兼容性证据和迁移说明重新提高下限。

## 回滚条件

只有在基准、正确性或安全要求证明 Python 3.11 无法满足核心协议，且存在可用迁移路径时，才能以新 ADR 提高最低版本。
