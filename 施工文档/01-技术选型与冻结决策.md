# 技术选型与冻结决策
## ADR 基线 v3.0

> 本文是后续施工的技术合同。除非新增证据触发 ADR 变更，否则按本文实施。

---

## 1. 选型原则

技术选型按以下优先级排序：

1. 长篇一致性与可恢复性
2. 不依赖 API Key
3. 跨 IDE Agent 可执行
4. 可审计、可回滚、可迁移
5. 零第三方依赖的基础路径
6. 性能与可扩展性
7. 新技术的可插拔性
8. 开发便利性

“更现代”“更复杂”“社区更大”不能单独成为选型理由。

---

## 2. 已冻结的技术决策

### ADR-0001：主语言选择 Python 3.11+（由 ADR-0013 修订）

**决策：** 核心使用 Python 3.11 及以上版本；3.11 作为最低兼容版本。版本下限调整依据见 `11-ADR-0013-Python最低版本调整.md`。

**理由：**

- IDE Agent 普遍可以直接执行 Python。
- `sqlite3`、`json`、`pathlib`、`argparse`、`hashlib`、`datetime`、`dataclasses`、`unittest` 足以构成基础内核。
- 文本处理、批处理、文件原子落盘和 CLI 都适合 Python。
- 便于未来接入本地模型、Tokenizer、向量或科学计算扩展。
- 不把系统绑到 Node、Rust 或特定 Agent SDK。

**约束：**

- 核心路径不得依赖第三方包。
- 第三方库只能放进 optional extras，并有降级路径。
- 代码必须可以用 `python studio.py ...` 直接运行。

**不选：**

- Node.js：适合 IDE 插件，但不适合作为零依赖故事内核首选。
- Rust：适合未来性能关键模块，不适合作为首期 Agent 可读、可修改的主实现。
- Python Web 服务：本项目首期不是服务化产品，不增加常驻服务依赖。

### ADR-0002：权威存储采用事件日志 + SQLite 派生投影

**决策：**

```text
append-only JSONL event log      权威历史
SQLite database                  查询与物化投影
Markdown/JSON artifacts          人类可读产物与证据
```

**理由：**

- 事件日志可以重放、审计、分支和恢复。
- SQLite 标准库可用，适合本地、单书、单用户生产。
- SQLite 查询远胜于扫描百万字 Markdown。
- 派生状态损坏时可从事件日志重建。
- 不依赖服务器、云端数据库或图数据库。

**关键原则：**

- SQLite 不是唯一真相；它是可重建投影。
- 正文不是唯一真相；正文是证据和候选事实来源。
- 任何权威状态变化必须先有事件或与事件同事务提交。
- 事件不可静默修改；纠错使用反向事件或 supersede 关系。

**事件路径：**

```text
workspace/<book>/ledger/events.jsonl
workspace/<book>/state/state.db
workspace/<book>/runs/<run_id>/
workspace/<book>/snapshots/<snapshot_id>/
```

### ADR-0003：对象化模型采用 Object + Facet + Relation

**决策：**采用稳定对象 ID，加可扩展 Facet，不为每种题材硬编码一套表。

```text
Object      稳定身份与生命周期
Facet       某种维度的属性/状态
Relation    对象之间有类型、有时间、有证据的关系
Event       造成变化的事实
```

示例：

```text
object: char_lin_yun
facets:
  identity
  psychology
  capability
  appearance
  voice
  knowledge
  resource
relations:
  belongs_to
  knows
  owes
  located_at
  opposes
  possesses
  affects
```

**理由：**

- 适配通用题材。
- 支持用户偏好的“万物 Object 化”。
- 新增题材维度时添加 Facet，不修改核心表结构。
- 保留确定性字段和来源，避免 JSON 黑箱。

**约束：**

- Facet 不是无 schema 的任意字典；每个 Facet 有版本化 schema。
- 任何关键字段必须有类型、来源、有效期或置信度。
- 不允许 Agent 随意新增无法解析的 Facet 类型。

### ADR-0004：时间采用双时态 + 叙事序

**决策：**任何会变化的事实至少支持：

```text
valid_from / valid_to       故事世界中的有效时间
recorded_at                 系统首次记录时间
recorded_event_id           写入该事实的事件
story_seq                   章节/场景/事件叙事序
```

必要时增加：

```text
revealed_at                 读者或角色何时得知
invalidated_by              哪个事件使其失效
```

**理由：**

- 支持倒叙、闪回、真相追溯、不可靠叙事。
- 区分“事实何时成立”和“系统何时知道”。
- 支持“截至第 N 章查询世界状态”。
- 支持角色知识与读者知识延迟。

**禁止：**

- 直接覆盖旧事实。
- 只用章节编号代表世界时间。
- 把后期揭露的真相伪装成早期角色已知事实。

### ADR-0005：模型运行时以 IDE Agent 为默认

**决策：**默认模型入口是 IDE 内置 Agent，不要求任何 API Key。

```text
ModelRuntime
├── ide_agent      默认，Antigravity 优先
├── local_model    可选，Ollama/本地兼容服务
└── api_model      可选，用户自行配置
```

**理由：**

- 符合用户硬约束。
- Antigravity/Claude Code/Cursor/Codex 自带模型、工具和 Agent 环境。
- 项目只负责协议、上下文、状态与验证，不负责托管模型。
- 换模型不会破坏故事数据库。

**降级能力：**

没有模型时仍可执行：

```text
init / doctor / outline check / state rebuild / audit
snapshot / rollback / reconcile / export / test
```

### ADR-0006：Agent 交换格式采用 ContextPack + ArtifactBundle

**决策：**不把 IDE 对话 transcript 作为接口；Agent 通过文件产物交换。

```text
ContextPack       生产前由系统生成的最小上下文包
ArtifactBundle    Agent 生产出的候选产物包
StateDelta       经验证后才能应用的状态变更
EvidenceBundle   所有判断的原文区间与来源
```

**理由：**

- 跨 IDE。
- 跨模型。
- 可测试、可回放、可审计。
- 防止模型上下文和业务状态耦合。
- 方便人类直接编辑和检查 Markdown/JSON。

---

### ADR-0007：默认不引入向量数据库和图数据库

**决策：**首期使用 SQLite 精确查询、关系表、事件表和可选 FTS5；语义检索是可选插件。

**理由：**

- 长篇一致性首先需要精确实体、时间、关系和证据，不是相似度。
- 向量检索无法保证新旧事实、权限和时间边界。
- 图数据库增加部署和迁移成本。
- 未来可增加向量/图插件，但不能让它们成为唯一依据。

**优先检索顺序：**

```text
ID/精确实体
→ 时间和关系过滤
→ FTS5/倒排
→ 语义候选召回
→ Agent 解释与选择
→ 权威状态校验
```

### ADR-0008：核心依赖标准库优先，测试基线使用 unittest

**决策：**基础工程不需要 `pip install` 才能运行。

可选依赖未来包括：

- `pytest`：开发体验
- `jieba`/其他中文分词：增强统计
- `numpy`：熵和数值计算
- `networkx`：复杂图算法
- `sqlite-vec`/向量库：实验性语义检索
- `transformers`/`ollama`：本地模型

**理由：**

- 用户要求“丢进 IDE 直接跑”。
- 可离线执行。
- 防止依赖安装错误遮蔽系统错误。
- 核心算法可移植、可审计。

---

### ADR-0009：固定章级生产协议，章内递归自适应

**决策：**

```text
书/卷/章：固定生产阶段与闸门
章内 beat：按任务复杂度动态递归拆分
```

**理由：**

- 长篇连载是重复生产任务，需要可标定和可恢复。
- 复杂战斗、谈判、推理和多线交汇需要不同深度。
- 固定每章四个 beat 或固定字数会导致结构僵化。
- 完全动态的工作流难以回归、难以调度。

---

### ADR-0010：正文自由生成，结构化信息后置抽取

**决策：**

```text
写手：自由生成 prose
抽取器：读取 prose，生成 candidate claims/state_delta
引擎：schema + invariant + evidence 验证
```

**理由：**

- 避免 Format Tax。
- 避免模型同时承担文学写作和 JSON 序列化。
- 允许不同模型负责写作与抽取。
- 结构化状态不直接信任写手输出。

---

### ADR-0011：多 Agent 只用于隔离，不用于共享权威写入

**决策：**

- Writer 可以写候选正文。
- Extractor 可以写候选结构化数据。
- Auditor 只读并产出报告。
- Librarian 只读正文和报告，生成建议。
- Reconciler 是确定性代码，应用状态变更。

Agent 之间传递 ArtifactBundle，不传完整聊天记录。

---

### ADR-0012：高级技术一律作为插件

Cartridge、扩散编辑、激活空间控制、StoryReward、BoN、bandit 路由均不得成为核心依赖。

所有实验技术必须满足：

1. 有 adapter 接口。
2. 失败可回到默认路径。
3. 输出必须经过同一验证层。
4. 有实验标识和版本。
5. 不能直接覆盖权威历史。

## 3. 技术淘汰表

| 候选 | 决定 | 原因 |
|---|---|---|
| 常驻 Python API 服务 | 首期不选 | 增加部署层，不符合 IDE-first |
| Neo4j | 首期不选 | 图查询价值不足以抵消依赖和部署成本 |
| 向量数据库 | 首期不选 | 相似度不能替代精确事实 |
| 全文 RAG | 不作为主方案 | 需要状态过滤和证据链 |
| LangChain/LangGraph | 不作为核心依赖 | 核心应独立于框架，必要时做 adapter |
| 全自动云 Agent | 不选 | 违反本地和无 API Key 约束 |
| 多 Agent 群聊 | 不选 | 协调故障、上下文污染、不可审计 |
| 直接 JSON 写作 | 不选 | 文学质量和推理受 Format Tax 影响 |
| 1M context | 不作为一致性方案 | context rot 仍存在 |
| 单一 LLM Judge | 不选 | 召回率、偏置和自评问题 |
