# 核心协议与数据模型规范
## Object / Facet / Event / ContextPack / Artifact v3.0

> 本文定义模块之间的“线”。后续任何代码、Skill、IDE 适配都不得绕过这些协议直接写权威状态。

---

## 1. 数据权威层级

从高到低：

```text
A 事件日志 events.jsonl                 不可删除的变更历史
B 结构化权威状态 state.db                事件重放得到的投影
C 已确认的正文 chapters/                 经过提交闸门的文本
D 候选运行产物 runs/<run_id>/            未确认结果
E Agent 对话和临时上下文                 不作为事实
```

规则：

- D 不能直接写 B。
- C 的新事实必须经过抽取、证据绑定和 Reconciler。
- B 损坏可以从 A 重建。
- A 的事件必须引用产生它的 Run 或人工操作。
- E 永远不能作为恢复唯一依据。

---

## 2. ID 规范

所有长期存在的对象使用稳定字符串 ID：

```text
book_<slug>
vol_<number>
arc_<number>
ch_<number>
scene_<chapter>_<number>
beat_<chapter>_<number>
char_<slug>
place_<slug>
item_<slug>
faction_<slug>
thread_<slug>
ob_<slug>
event_<uuid-or-seq>
run_<date>_<counter>
```

规则：

- ID 一经提交不可复用。
- 名称可以变化，ID 不变。
- Agent 不得自行创建与已有对象相似但不同的 ID。
- 新对象先进入候选实体表，确认后才进入权威对象表。

## 3. Object / Facet / Relation

### 3.1 Object

```yaml
object_id: char_lin_yun
type: character
canonical_name: 凌云
aliases: [云舟]
status: active
created_event: event_00031
supersedes: null
```

必填：

- `object_id`
- `type`
- `canonical_name`
- `status`
- `created_event`

### 3.2 Facet

Facet 是对象的可扩展维度，但必须有 schema：

```yaml
object_id: char_lin_yun
facet_type: psychology
facet_version: 1
payload:
  current_motive: 找回师父遗骨
  fear_threshold: 0.72
  cognitive_bias: sunk_cost
  want: 真相
  fear: 发现自己一直被利用
valid_from: story:0001-01-01T00:00
valid_to: null
source_refs: [outline/cast.yaml#char_lin_yun]
```

首批 Facet 类型：

```text
identity
appearance
psychology
capability
voice
knowledge
resource
location
relationship
status
arc
style
constraint
```

### 3.3 Relation

关系必须类型化、带时间和证据：

```yaml
relation_id: rel_0088
subject: char_lin_yun
predicate: knows
object: fact_identity_sword_sect
valid_from: story:0007-06-03T10:00
valid_to: null
recorded_event: event_00127
confidence: confirmed
evidence_refs: [ch_007#p12]
```

禁止裸关系：`凌云 -> 知道 -> 身份` 必须拆成可查询的对象、事实和证据。

## 4. Event Envelope

每个事件使用统一外壳：

```json
{
  "event_id": "event_00127",
  "event_type": "relation.asserted",
  "book_id": "book_demo",
  "branch_id": "main",
  "parent_event_id": "event_00126",
  "story_seq": 127,
  "recorded_at": "2026-09-29T12:00:00+08:00",
  "actor_type": "reconciler",
  "actor_id": "studio.reconcile",
  "source_run_id": "run_20260929_003",
  "payload_hash": "sha256:...",
  "payload": {},
  "evidence_refs": [],
  "supersedes": null
}
```

### 4.1 event_type 首批枚举

```text
object.created
object.renamed
object.retired
facet.asserted
facet.superseded
relation.asserted
relation.invalidated
fact.asserted
fact.disputed
obligation.created
obligation.touched
obligation.fulfilled
obligation.deferred
obligation.subverted
obligation.retired
knowledge.granted
knowledge.retracted
intent.registered
reality.observed
scene.committed
chapter.committed
state.reconciled
audit.completed
snapshot.created
branch.created
branch.merged
```

### 4.2 事件规则

- `payload_hash` 必须可重算。
- 事件追加前检查 `parent_event_id` 是否为当前分支头。
- 分支合并必须留下 `branch.merged` 事件。
- 事件错误不能编辑原行；用新事件 supersede。
- 任何状态投影都必须记录 `last_applied_event_id`。

## 5. 双时态与三种序

### 5.1 世界时间

```text
valid_from / valid_to
```

表示事实在小说世界何时成立。

### 5.2 记录时间

```text
recorded_at / recorded_event_id
```

表示系统何时知道或接受这条事实。

### 5.3 叙事序

```text
story_seq / chapter_id / scene_order
```

表示读者在什么叙事位置看到它。

三者必须分开。倒叙事件允许 `valid_from` 早于 `recorded_at`，真相揭露允许 `revealed_at` 晚于事件真实发生时间。

## 6. Future Obligation：未来义务模型

```yaml
obligation_id: ob_master_betrayal
kind: foreshadowing | promise | goal | mystery | debt | setup | deadline
owner_id: thread_master_betrayal
created_at_story_seq: 12
expected_window:
  earliest: ch_030
  latest: ch_080
weight: 0.8
status: open
last_touched_seq: 42
payoff_event_id: null
allowed_resolution: [fulfilled, subverted, deferred, retired]
reader_visibility: concealed
source_refs: [outline/threads.yaml#master_betrayal]
```

状态只能按以下图转换：

```text
open → touched → fulfilled
open → deferred → touched
open → subverted
open → retired
```

禁止：

- 直接把 open 改成 fulfilled 而没有 payoff 证据。
- 关闭义务但没有正文证据。
- 让 Agent 通过“本章提到了”伪造履约。

## 7. 角色知识与读者知识

### 7.1 角色知识

```yaml
holder_id: char_lin_yun
knowledge_id: fact_master_betrayal
state: unknown | suspected | believed | confirmed | false_belief
known_from_seq: 42
known_by_event: event_00420
confidence: 0.7
source_refs: [ch_042#p8]
```

### 7.2 读者知识

读者是特殊对象 `_reader`，但不能访问角色内心或 Bible；只能通过已发布正文获得知识。

```yaml
holder_id: _reader
knowledge_id: fact_master_betrayal
state: unknown | clue | suspected | confirmed | misled
revealed_at_seq: 57
source_refs: [ch_057#p19]
```

张力计算的基础集合：

```text
R = reader knows
C = current POV character knows
T = story truth

R \ C       读者知道、角色不知道：戏剧性优势
C \ R       角色知道、读者不知道：悬念/谜团
T \ (R∪C)  双方都不知道的真实信息：潜在惊奇
R ∩ C       读者与角色共享：共谋感
```

## 8. 意图账本与实况账本

### 8.1 Intent Ledger

由大纲和章计划产生：

```yaml
beat_id: beat_147_03
intended_actions: [A1, A2]
intended_reveals: []
required_obligations: [ob_master_betrayal]
forbidden_changes: [char_lin_yun.allegiance]
```

### 8.2 Reality Ledger

由正文抽取和确定性分析产生：

```yaml
beat_id: beat_147_03
observed_actions: [A1, A2, A3]
observed_entities: [char_lin_yun, place_black_tower]
observed_claims: [claim_991]
observed_state_deltas: [delta_202]
```

### 8.3 Reconcile

差异分类：

```text
intent_fulfilled
intent_missing
intent_changed_with_approval
emergent_valid
emergent_unregistered
contradiction
hard_violation
```

涌现不是自动错误，但必须明确登记为 `emergent_valid` 或被拒绝。

## 9. ContextPack 协议

写手每次只接收当前任务的最小上下文：

```yaml
pack_version: 1
book_id: book_demo
chapter_id: ch_147
beat_id: beat_147_03
task_kind: draft_beat
objective: ...
constraints:
  pov: char_lin_yun
  tense: past
  target_words: 800
  must_include: [...]
  must_not_include: [...]
authoritative_context:
  active_entities: [...]
  current_facts: [...]
  character_knowledge: [...]
  reader_knowledge: [...]
  open_obligations: [...]
  time_window: ...
recent_text:
  full: last_scene.md
  summaries: [...]
intent_contract: intent/beat_147_03.yaml
context_budget:
  hard_limit_chars: 28000
  target_fill_ratio: 0.55
output_contract:
  required_files: [prose.md]
  optional_files: [writer_notes.md]
forbidden_actions:
  - modify_state_db
  - append_events
  - rename_authoritative_object
```

核心原则：写手只写候选正文，不直接写 `state.db` 或 `events.jsonl`。

## 10. ArtifactBundle 协议

```text
runs/<run_id>/
├── request.yaml
├── context-pack.yaml
├── prose.md
├── writer-notes.md
├── candidate-claims.json
├── candidate-state-delta.json
├── candidate-obligations.json
├── extraction-report.json
├── audit-report.json
├── metrics.json
├── evidence.json
└── final-status.json
```

### 状态

```text
created
→ generated
→ extracted
→ checked
→ approved
→ committed
```

失败分支：

```text
generated → rejected
checked → needs_rework
approved → commit_failed
```

任何未到 `committed` 的产物都不能进入已发布章节。

## 11. 退出码契约

```text
0  成功
1  输入或配置错误
2  schema/格式错误
3  硬一致性违规
4  需要人工审批或存在未决冲突
5  运行环境/权限/依赖错误
6  状态投影或事件重放错误
7  资源/预算/并发保护触发
```

IDE Agent 必须依据退出码行动：

- `0`：继续下一步。
- `1/2`：修复输入或产物，不提交状态。
- `3`：禁止发布，生成修复任务。
- `4`：停在人类断点。
- `5/6/7`：保留运行产物，先恢复系统，不重写正文。

## 13. 协议验收

协议阶段完成必须通过：

1. 创建一个角色、地点、事实、关系和未来义务。
2. 追加至少 10 个事件。
3. 重放事件得到同样的 SQLite 投影。
4. 构造一次倒叙和一次后期真相揭露。
5. 构造一次角色不知道但读者知道的状态。
6. 构造一次正文涌现实体并进入人工确认队列。
7. 破坏一条事件 payload，系统能检测 hash 错误。
8. 从 snapshot 删除 SQLite 后，能从事件重建。
9. 任何失败不修改权威状态。
