# M3.3 Future Obligation 生命周期补充冻结决策
## Future Obligation Lifecycle v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M3.2 PASS
- 影响范围：obligation 权威载荷、状态机、证据门槛、as-of 列表

## 1. 评估与冲突处理

核心协议已有 `obligation.created/touched/fulfilled/deferred`，但允许结局包含 `subverted/retired`，事件词表却无法表达后二者；原状态图也无法同时满足多条 clue 和“关闭前须有证据”。本决策作正式加法修正：

- core.v3 `EVENT_TYPES` 新增 `obligation.subverted`、`obligation.retired`；
- active 状态为 `open | touched | deferred`，terminal 状态为 `fulfilled | subverted | retired`；
- 为支持多个伏笔证据，允许 `touched → touched`；
- 为支持重新排期，允许 `touched → deferred`；
- `fulfilled/subverted` 必须从 `touched` 进入并通过 payoff 证据门；
- `retired` 可从任一 active 状态进入，但必须有明确批准/正文来源和理由。

这是对既有协议不可表达部分的补充，不改变 Event Envelope 版本。

## 2. 阶段边界

M3.3 实现：

- bootstrap obligation 的 canonical authority record；
- created/touched/deferred/fulfilled/subverted/retired 的 lineage 折叠；
- clue 数量、payoff requirement、allowed resolution、时间窗和来源不变量；
- event/head/chapter as-of 列表与 due/overdue 分类；
- 确定性、只读 `obligation-state.v1` 报告。

不实现 Intent/Reality、张力评分、impact、ContextPack、生产 Agent 或正文。

## 3. Canonical obligation v1

`obligation.created` 载荷为：

```json
{
  "obligation": {
    "obligation_id": "ob_master_betrayal",
    "kind": "foreshadowing",
    "owner_id": "thread_master_betrayal",
    "created_at_story_seq": 0,
    "expected_window": {"earliest": 80, "latest": 140},
    "weight": 0.9,
    "status": "open",
    "last_touched_seq": null,
    "payoff_event_id": null,
    "allowed_resolution": ["fulfilled", "subverted", "deferred"],
    "reader_visibility": "concealed",
    "evidence_requirement": {"min_clues": 2, "payoff_requires": ["event_master_truth_revealed"]},
    "source_refs": ["compiled:.../obligations.json#ob_master_betrayal"]
  },
  "evidence": []
}
```

- `created_at_story_seq` 必须等于 carrying event `story_seq`；
- window 为正整数且 `earliest <= latest`；
- weight 为 `[0,1]` 有限数；
- 初始 status 固定 `open`，touch count 和 defer count 由折叠器派生；
- bootstrap 必须把 Outline Package obligation 显式转换成此协议，不能把大纲原始对象直接伪装成权威模型。

## 4. Transition 载荷与证据

共同字段：`obligation_id`、`source_event_id`、非空 `source_refs`、`evidence`。

- `touched`：增加 `touch_kind = clue | reminder | escalation`；只在 `touch_kind=clue` 时增加 clue count。
- `deferred`：增加 `new_expected_window` 和非空 `reason`；新 latest 必须严格晚于旧 latest，且 resolution `deferred` 必须被允许。
- `fulfilled/subverted`：增加 `payoff_event_id` 和非空 `satisfied_requirements`；对应 resolution 必须被允许。
- `retired`：增加非空 `reason`，resolution `retired` 必须被允许。

`source_event_id/payoff_event_id` 必须引用 selected lineage 中更早的 `scene.committed`、`chapter.committed` 或（仅 retired）`audit.completed`。仅“本章提到了”的自由文本不能作为关闭证据。

`fulfilled/subverted` 的硬门槛：

1. 当前状态为 `touched`；
2. `clue_count >= min_clues`；
3. `satisfied_requirements` 覆盖创建时全部 `payoff_requires`；
4. payoff event 是更早的 committed scene/chapter。

## 5. 状态转换

```text
open     → touched | deferred | retired
touched  → touched | deferred | fulfilled | subverted | retired
deferred → touched | retired
terminal → 无后续转换
```

任何未列出的转换、重复创建、未知 obligation、terminal 后事件均为完整性错误。

## 6. 查询与逾期

命令：

```bash
python studio.py obligation list --book book_demo --as-of ch_010 [--status active]
```

支持 M3.1 相同的 `head | event_<id> | ch_<positive>`、branch 和 `--json`。Obligation 是叙事未来承诺，不使用 world valid-at。

对 chapter selector：

- active 且 chapter `< earliest`：`scheduled`；
- active 且 `earliest <= chapter <= latest`：`due`；
- active 且 chapter `> latest`：`overdue`；
- terminal：`closed`。

head/event selector 没有明确章节目标时，以 cutoff `story_seq` 作为位置。`--status` 支持具体状态、`active`、`terminal`、`due`、`overdue`；省略返回全部。

## 7. 输出、只读性和错误

`obligation-state.v1` 包含 branch、cutoff、status filter、稳定排序 obligations、active/terminal/due/overdue 计数和 canonical hash，不含墙钟时间。

查询严格只读。非法输入退出 `1`；chapter 叙事序硬不变量退出 `3`；EventLog、模型、状态机或证据完整性错误退出 `6`。
