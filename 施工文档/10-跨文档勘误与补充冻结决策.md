# 跨文档勘误与补充冻结决策
## Implementation Clarifications v1.0

> 本文件不是推翻原架构，而是把原文档中对新会话不够明确、容易产生分叉实现的地方冻结下来。

---

## 1. 决策优先级

当不同文档的示例、路径或措辞不一致时，优先级为：

```text
本文件
→ 09-M0精确施工与验收附录
→ 01-技术选型与冻结决策（ADR）
→ 02-核心协议与数据模型规范
→ 04-分阶段施工计划
→ 03/05/06/07 中的执行示例
```

低优先级文档中的示例不能覆盖高优先级文件中的合同。

---

## 2. 路径勘误：v2 是实际工程根

冻结如下：

```text
仓库根：       /home/user/novel-pipeline/
设计文档：     /home/user/novel-pipeline/施工文档/
实际工程根：   /home/user/novel-pipeline/v2/
```

因此：

- `studio.py` 应位于 `v2/studio.py`；
- `novel_kernel/`、`schemas/`、`scripts/`、`tests/` 应位于 `v2/`；
- 书籍运行数据应位于 `v2/workspace/<book_id>/`；
- 从 `v2/` 执行时使用 `python studio.py ...`；
- 从仓库根执行时应显式使用 `python v2/studio.py ...`，但施工文档统一以 `v2/` 为当前目录。

原文档中没有 `v2/` 前缀的路径，默认解释为“相对于实际工程根 `v2/`”。

## 3. Serialization Policy：机器格式与人类格式分层

### 3.1 核心权威格式

首期核心只把以下格式作为运行时权威输入/输出：

```text
JSON       结构化单对象、配置、报告、候选状态
JSONL      append-only 事件日志
SQLite     派生查询投影
Markdown   正文、说明、人工可读报告
```

### 3.2 YAML 的边界

原施工文档使用 `.yaml` 作为人类可读的结构化示例。现在冻结为：

- `tech-stack.yaml`、`exit-codes.md`、`directory-contract.md` 是工程合同文件，其中 YAML 可以先作为人类阅读文件；
- M0 不实现通用 YAML 解析器；
- 核心内核不得因为没有 YAML 包而不能启动、诊断、重建或测试；
- Outline Package v1 可以保留 YAML 作为作者输入格式，但必须通过 `StructuredDocumentLoader` 接口加载；
- 无第三方依赖的基线测试使用等价 JSON fixture；
- YAML 解析器是可替换适配器。若环境没有可选 YAML 依赖，系统必须给出明确的环境错误，不得静默按不完整规则解析；
- 任何编译后的权威产物必须同时有 JSON 形式，便于重放、校验和跨 IDE 使用。

因此，“不依赖 API Key”和“基础内核零第三方依赖”仍然成立，但不等于 M2 的所有作者输入适配器都必须用标准库解析 YAML。

### 3.3 禁止事项

- 不要自己在 M0 编写一个半兼容 YAML 解析器；
- 不要把 Python `repr` 当作结构化格式；
- 不要把模型输出的 YAML/JSON 直接当作权威状态；
- 所有候选结构化输出都必须先过 schema、证据和 Reconciler。

## 4. 版本和状态边界

冻结以下版本标识：

```text
工程版本：0.1.0-dev
协议代际：core.v3
大纲规格：outline.v1
ArtifactBundle：artifact.v1
ContextPack：context.v1
```

版本含义：

- 工程版本描述代码发行状态；
- 协议代际描述字段/语义兼容边界；
- 任何协议不兼容变更必须提高代际或写迁移器；
- `version` 命令不能只打印 Python 版本，必须打印工程版本和当前里程碑。

---

## 5. 时间与哈希规范补充

### 5.1 时间

- 所有机器记录的 `recorded_at` 必须是带时区的 ISO 8601/RFC 3339 字符串；
- 内部比较统一转换为 UTC；
- `valid_from`、`valid_to`、`revealed_at` 属于故事时间，不得与记录时间混用；
- 时间未知时使用显式状态 `unknown` 或区间，不得伪造 `1970-01-01`；
- 叙事序 `story_seq` 是整数/有序键，不得通过时间戳替代。

### 5.2 JSON 哈希

所有 payload/artifact hash 必须基于同一规范化过程：

```text
UTF-8
→ JSON object keys sort_keys=true
→ separators=(',', ':')
→ 不附加换行
→ SHA-256
```

Markdown、原始正文和二进制文件则对原始字节计算 SHA-256。

哈希字符串统一使用：

```text
sha256:<64位小写十六进制>
```

## 6. Event ID 和事件顺序补充

为避免分支和并发时事件 ID 冲突：

- `event_id` 采用 `event_` + 小写 UUID4 十六进制串；
- 示例中的 `event_00127` 仅用于说明，不是实现格式；
- `story_seq` 表示叙事序，不表示事件日志物理行号；
- 事件日志的物理顺序由 JSONL 行顺序决定；
- 每个分支必须维护唯一 `parent_event_id` 和 branch head；
- append 前必须锁定日志，确认 parent 仍是当前 head，写入并 fsync 后才能更新 head；
- 并发冲突必须失败并返回退出码 `7`，不能静默覆盖或自动重排。

## 7. Agent 权限的现实边界

“Writer 不能写 state.db”分为两层：

### 7.1 协议层

Skill、ContextPack、Run 目录和 `studio.py` 命令都会限制写入范围。这是 M0–M5 必须实现的确定性检查。

### 7.2 操作系统层

Antigravity、Claude Code、Cursor、Codex 的 sandbox/approval 配置可以进一步限制文件系统权限，这是 M7 适配工作。

在 M0–M6，不得宣称 Python 脚本已经实现了不可绕过的 OS 级沙箱。正确说法是：

```text
核心提交路径具有确定性校验；IDE sandbox 是额外防线。
```

任何 Run 如果检测到权威文件在非授权路径被改动，必须：

1. 标记 Run 为违规；
2. 保留证据；
3. 阻断 commit；
4. 不尝试“自动修复后继续”。

## 8. 事件、投影和正文的提交边界

冻结为：

```text
candidate artifact
→ schema validation
→ evidence binding
→ deterministic reconcile
→ hard invariant check
→ append event
→ rebuild/update projection
→ commit marker
```

在事件追加成功前：

- 不得更新已发布章节；
- 不得把 candidate object 变成 canonical object；
- 不得删除原 Run；
- 不得覆盖旧版本正文。

在投影更新失败时：

- 事件日志仍保留；
- 投影标记为 stale；
- 退出码为 `6`；
- 优先从事件日志重建，不手工改 SQLite。

## 9. 文件命名和兼容性补充

- 文件名和目录名使用 ASCII、小写、短横线或下划线；
- 施工文档可以使用中文文件名；
- ID 使用 ASCII 稳定字符串；
- 用户正文、角色名、标题可以使用 Unicode；
- 所有 JSON 使用 UTF-8；
- 所有文本文件末尾保留换行；
- 跨平台路径一律通过 `pathlib` 处理，不拼接硬编码 `/`；
- Windows、macOS、Linux 的权限测试必须允许明确的 `SKIP`，但不能把未执行伪装成 PASS。

---

## 10. 文档和代码变更规则

下列变化必须写变更记录或 ADR：

- 修改退出码含义；
- 修改事件 Envelope 字段；
- 修改权威层级；
- 修改目录契约；
- 把可选依赖变成必需依赖；
- 修改 Outline Package 的必填字段；
- 修改 Agent 的授权写入范围；
- 修改 M0–M8 顺序或退出条件。

普通实现 bug 可以直接修复，但必须补测试。

---

## 11. 对旧文档示例的解释

旧文档中的以下内容属于概念示例，不得直接复制为最终实现格式：

- `event_00127` 形式的事件 ID；
- `.yaml` 文件中的伪字段；
- `production-manifest.yaml` 作为唯一机器产物；
- 未注明工作目录的相对命令；
- “Writer 不能写权威状态”作为没有校验证据的口头承诺。

实现时以本文件、M0 附录、JSON Schema 和实际测试为准。
