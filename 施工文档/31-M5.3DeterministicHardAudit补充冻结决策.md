## 1. 首批检查

M5.3 实现只读、确定性的 `audit hard`。它重验 M5.1–M5.2 完整性链，并检查首批可由结构化 candidate fact 表达的硬不变量：

- 继承 reconcile 的 unregistered subject、forbidden change、contradiction；
- `acts`：死亡角色不得行动；
- `story_time`：候选时间必须落在本章冻结时间窗口；
- `location`：地点必须是已注册 place，且首版必须等于本章冻结 location（跨地点移动/可达图推迟）；
- `knows`：角色只能声明冻结 knowledge edge 中已有 fact；
- `capability_use`：能力必须存在于角色冻结 capability facet；
- `resource_use`：资源必须是已注册 item 且有冻结 `possesses` relation；
- `obligation_touch`：义务必须位于冻结 open obligations；
- required change missing 与 emergent candidate 保留为 review finding，不冒充 hard。

这些 predicate 是首版 audit vocabulary；其他 predicate 不由本切片推断语义。

## 2. 状态与结果

```text
reconciled | reconcile_review | reconcile_blocked
→ audit_pending
→ audit_passed | audit_review | audit_failed
```

`audit_passed` 返回 0；review 返回 4；hard failure 返回 3。Finding 必须含稳定 ID、rule ID、severity、candidate item/claim、evidence IDs 与结构化 message。不得使用模型评分。

## 3. CLI

```bash
python studio.py audit hard (--book ID | --path PATH) --run run_<hash> [--json]
```

输出 `hard-audit-report.json`，重复执行同输入 byte-idempotent。同路径不同 bytes 为完整性错误。

## 4. 安全边界

Auditor 读取冻结 ContextPack、candidate extraction 和 candidate reconcile，只写 Run report/status；不修改正文、candidate delta、EventLog、SQLite、compiled 或 chapters。每次 audit 前重新确认 authority head 与 compile pointer 未漂移。

## 5. 明确排除

不实现跨地点图寻路、自然语言动作识别、开放语义/风格/商业审计、人工批准、事件生成、章节发布或权威提交。M5.4 才评估语义/风格报告与 rework gate。
