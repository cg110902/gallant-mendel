# M5.2 Candidate Reconcile 与硬闸门前置分类补充冻结决策
## Candidate Reconcile v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M5.1 PASS（14/14）

## 1. 最小切片

M5.2 对 M5.1 的 candidate fact deltas 做确定性 reconcile，但仍不写权威状态。输入必须绑定同一 approved prose、ContextPack、extraction hash、authority head 和 compile ID。

每个 delta 只进入一个主分类：

```text
unregistered_subject   hard
forbidden_change       hard
contradiction          hard
no_change              safe
intent_fulfilled       safe
emergent_candidate     human review
```

此外，对 Intent 中没有候选 delta 命中的 required change 生成 `intent_missing`，进入 human review。

## 2. 比较语义

- authority baseline 使用冻结 ContextPack 内 active facts，不读取未来状态；
- key 为 `(subject_id,predicate)`，value 使用 canonical JSON 等值；
- 同 key 同 value 为 `no_change`；同 key 不同 value 为 `contradiction`；
- required/forbidden change 采用结构化签名 `subject.predicate=value`，禁止模糊文本匹配；
- 未注册 subject 无论意图如何均为 hard；
- evidence ID、span、quote、prose hash、claim/delta 引用任何断裂都是完整性错误，不降级为普通分类。

## 3. 状态与退出码

```text
extracted → reconcile_pending
reconcile_pending → reconciled        (无 hard、无 review)
reconcile_pending → reconcile_review  (emergent 或 missing)
reconcile_pending → reconcile_blocked (hard)
```

CLI：

```bash
python studio.py reconcile (--book ID | --path PATH) --run run_<hash> [--json]
```

`reconciled` 返回 0，`reconcile_review` 返回 4，`reconcile_blocked` 返回 3；输入错误 1，stale 3，完整性错误 6。原有 `reconcile diff` 查询保持兼容。

## 4. 安全边界

只写 `runs/<run_id>/candidate-reconcile.json` 与 run status。重复执行同输入必须 byte-idempotent；不得修改 candidate extraction、EventLog、SQLite、compiled、chapters。

## 5. 明确排除

本切片不是 Auditor，不实现死亡行动、时间可达性、知识泄漏、能力前置、义务生命周期等完整硬闸门，也不批准 emergent candidate，不生成权威事件、不发布章节。M5.3 才评估 hard invariant audit 的第一批可确定性检查。
