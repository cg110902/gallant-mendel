# M4.2 Writer Runtime 与 Run 控制补充冻结决策
## Isolated Candidate Writer v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M4.1 PASS（12/12）

## 1. 评估结论与最小切片

M4.2 实现任务级 Runtime 接口、Writer Skill 初版以及 `start/status/resume/abort`。本阶段允许在 Run 目录生成候选 `prose.md`，但不做抽取、审计、章节发布或 EventLog commit。

首个可验收 Runtime 为确定性 `offline` adapter；它用于协议、恢复和权限回归，不宣称具备文学质量，也不访问网络或模型 API。真实模型 provider 只能在相同接口与证据边界下后续接入。

## 2. 输入、输出与权限

- Writer 的唯一业务输入是已冻结且 hash 匹配的 `context-pack.json`；CLI 参数、环境和对话历史不得成为隐式故事输入；
- Harness 读取 task/request/status，但 Runtime 只收到不可变 `RuntimeRequest(context_pack_bytes, context_hash, attempt_id)`；
- Runtime 返回内存中的 `RuntimeResult`，Harness 只向 `runs/<run_id>/` 发布；
- 输出包括 attempt request/result、stdout/stderr、候选 prose、可选 writer notes 和根级 `prose.md`；
- start/resume 前后对 `ledger/events.jsonl`、`ledger/heads.json`、`state/state.db`、`compiled/current.json` 做 byte hash 哨兵；任何改变标记 `violated`，退出 `6`，且不得自动修复；
- 这是协议层防线，不宣称 OS 级不可绕过 sandbox。

## 3. 状态机与恢复

M4.2 允许：

```text
context_ready → writer_running → draft_ready
writer_running → writer_failed
context_ready | writer_running | writer_failed → aborted
writer_running | writer_failed → writer_running  (resume，新 attempt)
```

`start` 只接受 `context_ready`；`resume` 只接受 `writer_running` 或 `writer_failed`；`abort` 幂等。每次 attempt 单独保存，不能覆盖历史 attempt。根级候选正文仅在成功后原子发布；已存在且 bytes 不同视为完整性冲突。

## 4. CLI 与错误

```bash
python studio.py run start (--book ID | --path PATH) --task task_<hash> [--runtime offline]
python studio.py run status (--book ID | --path PATH) --run run_<hash>
python studio.py run resume (--book ID | --path PATH) --run run_<hash> [--runtime offline]
python studio.py run abort (--book ID | --path PATH) --run run_<hash>
```

输入/非法转换 `1`，stale context `3`，写入失败 `5`，完整性/越权 `6`。Runtime 失败保留 stdout/stderr 和 result，状态为 `writer_failed`，返回 `1`。

## 5. 明确排除

不接真实 provider、不读取 API key、不执行任意 shell、不抽取 claim、不自动审计、不修改 authority、不发布 `chapters/`。`draft_ready` 只表示候选文件完整，不表示小说质量或可提交。
