# M1.4 投影与事件载荷补充冻结决策
## SQLite Projection and Event Payload Mapping v1

- 状态：已接受
- 日期：2026-09-29
- 影响范围：M1.4 SQLite 派生投影与事件重放
- 性质：对 core.v3 事件 payload 和分支投影语义的向前兼容补充

## 1. 权威边界

- `ledger/events.jsonl` 仍是权威历史。
- `state/state.db` 只保存可删除、可重建的派生查询状态。
- 投影中的每张业务表固定 `authority = derived`。
- 不允许通过直接编辑 SQLite 创建权威事实。
- 重建失败时旧数据库保持不变；增量事务失败时整体回滚。

## 2. 分支投影

每个 `state.db` 只投影一个分支，M1.4 默认 `main`。

投影事件集合不是“所有同名 branch_id 的行”，而是从目标 branch head 沿 `parent_event_id` 反向追溯到根后再正序排列的 lineage。这样新分支会继承分叉点之前的祖先状态，但不会混入其他分支后续事件。

投影 metadata 必须包含：

```text
schema_version
branch_id
authority
last_applied_event_id
applied_event_count
```

增量更新前必须确认数据库中的 projected event ID 序列仍是当前 lineage 的前缀，否则标记 stale 并拒绝继续。

## 3. 可投影事件 payload v1

以下事件具有确定性业务投影：

```text
object.created       {"object": Object, "evidence": [Evidence, ...]}
object.renamed       {"object_id": ID, "canonical_name": str, "aliases": [str, ...]}
object.retired       {"object_id": ID}
facet.asserted       {"facet": Facet, "evidence": [Evidence, ...]}
facet.superseded     {"object_id": ID, "facet_type": str}
relation.asserted    {"relation": Relation, "evidence": [Evidence, ...]}
relation.invalidated {"relation_id": ID, "valid_to": story-time}
fact.asserted        {"fact": Fact, "evidence": [Evidence, ...]}
fact.disputed        {"fact_id": ID, "evidence": [Evidence, ...]}
```

`evidence` 在 create/assert/dispute 事件中固定存在，可以为空；Relation/Fact 自身的 evidence refs 仍必须满足 M1.3 约束。

其他已冻结 event type 在 M1.4 只进入 `projected_events` 审计表，不改变上述五类业务表。后续里程碑增加相应投影处理器时必须补测试；不得静默把未知 event type 当成成功。

## 4. 事件与记录绑定

- `Object.created_event` 必须等于承载它的 `object.created.event_id`。
- Facet、Relation、Fact、Evidence 的 `recorded_event` 必须等于首次承载它的事件 ID。
- Evidence ID 不得重复创建。
- object rename/retire、facet supersede、relation invalidate、fact dispute 的目标必须已存在于当前 lineage 投影。
- Relation 两端、Fact subject、Facet 内部引用必须在应用时解析成功。
- 任何一项失败都回滚整个 SQLite 事务。

## 5. SQLite v1 表

```text
projection_meta
projected_events
objects
facets
relations
facts
evidence
```

- JSON 子结构以 core.v3 规范 JSON 文本保存。
- `projected_events` 保存 lineage 中完整规范 Event Envelope，便于检查投影前缀和来源。
- 当前 Facet 以 `(object_id, facet_type)` 为主键；新 `facet.asserted` 替换当前派生值，历史仍在事件日志。
- `facet.superseded` 从当前 Facet 投影删除，不删除历史事件。
- 所有外键检查开启。
- `PRAGMA user_version = 1`，`synchronous = FULL`。

## 6. 原子重建

重建流程：

```text
读取并验证 EventLog
→ 计算目标分支 lineage
→ 在同目录临时 SQLite 中建表
→ 单事务应用 lineage
→ integrity_check + foreign_key_check
→ fsync 临时数据库
→ os.replace state.db
→ fsync state 目录
```

如果任何步骤失败：

- 删除临时数据库；
- 保留旧 `state.db`；
- 返回投影/重放错误语义；
- 不修改事件日志。

## 7. 查询边界

M1.4 只提供当前投影查询和完整表导出，不实现 M3 的双时态 as-of 查询。故事时间字段原样保留，为 M3 查询做准备。
