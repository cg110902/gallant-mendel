# M6.7 三十章 Soak 与断点续跑补充冻结决策
## Controlled Sequential Soak v1

- 状态：已接受
- 日期：2026-09-30
- 前置：M6.6 PASS（20/20）

## 1. 评估结论

M6 原始退出条件要求 30 章压测中断后可继续。M6.6 已证明三章连续性和单次恢复，但不足以覆盖更长 EventLog、Run artifact 累积及多恢复点。M6.7 因此只扩展到**顺序 30 章 controlled soak**；遵循“先可恢复，后并发”，并发冲突测试留给后续阶段。

本阶段记录实际 elapsed time 仅用于证据，不设置性能阈值，也不据此声明吞吐、容量或生产 SLA。

## 2. 冻结执行

`ch_001..ch_030` 逐章执行完整 M5/M6.5 链：plan、context、writer/review、extract、reconcile、hard/soft/advisory、human gate、commit。每章只提交一个唯一、结构化、intent-matched fact，使数量守恒可精确验证。

- 第 10 章后创建 verified snapshot，恢复至新的空目标并继续第 11 章；
- 第 20 章 commit 注入 deterministic EventLog prefix 中断，重试补齐后缀；
- 第 20 章发布后再创建 snapshot；
- 第 30 章后执行 EventLog、projection、temporal、chapter、Run receipt 总守恒检查。

## 3. CED

冻结三个不重叠十章窗口：`ch_001..010`、`ch_011..020`、`ch_021..030`。每窗 CED 为 hard consistency errors / 10；总体密度为 errors / 30。Advisory findings 单列并排除于 CED，不能升级 hard gate。

## 4. Silent-data-loss

失败条件包括：authority 数量不等于初值加各 commit event 数、parent/head 不连续、30 个 chapter event 或文件缺失、chapter hash 漂移、fact 在 temporal/projection 任一侧缺失、projection head 漂移、Run receipt 缺失、snapshot head 不等于对应 chapter commit head。任一失败都必须令 `silent_data_loss=true`。

## 5. 诚实边界

- 仅证明受控、顺序、单 writer、30 章样本可在两个恢复场景后继续；
- 不证明并发 writer、100 章性能、真实模型文本质量或百万字容量；
- elapsed time 不具有 benchmark/SLA 含义；
- M6.5 challenge 仍为 TP=9、FP=0、TN=18、FN=9；
- threshold 保持 warning-only，且不读取 soak 结果重新标定。

通过后下一步只能先评估 M6.8 并发冲突与资源保护，不得把顺序 soak 宣称为并发安全或生产可靠。
