# M4.1 Production Task DAG 与 ContextPack 补充冻结决策
## Deterministic Production Plan v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M3 总验收 PASS

## 1. 首个切片

M4.1 只实现确定性生产计划和 ContextPack 构建，不调用模型、不生成正文、不抽取或提交状态。

命令：

```bash
python studio.py plan chapter --book book_demo --chapter ch_001
python studio.py context build --book book_demo --run run_<hash>
```

## 2. 安全边界

- 计划目标必须是尚未提交的下一章；authority head 的 `story_seq` 必须小于目标章节号，防止未来状态泄漏；
- M2 readiness、current compile、authority head 和 source package hash 全部冻结进 request；
- task/run ID 由 canonical inputs 的 SHA-256 派生，不含墙钟和随机数；
- 重复相同输入幂等复用；同 ID 不同 bytes 为完整性错误；
- Planning 只能写 `production/tasks/` 与 `runs/<run_id>/`，不能写 EventLog、SQLite、chapters；
- Context build 前重新验证 authority head 与 compile pointer 未变化，变化则以 hard stale-plan 退出 `3`；
- Writer 未来只能读取 ContextPack 并写 run 目录，M4.1 不实现 Writer。

## 3. DAG 与状态

DAG 固定为：`draft → extract → audit → commit`。只有 draft 在 M4.1 可执行，其余是 future gate。Run 状态只允许：

```text
planned → context_ready
```

request、task、ContextPack 和 status 均为 canonical JSON。ContextPack 包含目标/POV/地点/时间、authority cutoff、active state、POV knowledge、reader knowledge、open obligations、intent contract、预算和 forbidden actions。

## 4. 输出与错误

协议：`production-task.v1`、`context-pack.v1`、`run-status.v1`。输入错误 `1`，stale/hard invariant `3`，文件/authority 完整性 `6`，环境写入失败 `5`。

## 5. 后续

M4.2 才实现模型运行时接口、Writer Skill 和 run start/resume/abort；M4.1 不产生 `prose.md`。
