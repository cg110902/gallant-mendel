# 大纲规格与编译规范
## Outline Package v1

> 大纲不是一段自由文本，而是小说生产系统的源代码。
>
> 本文定义作者、Architect Agent 和编译器共同使用的输入协议。

---

## 1. 总原则

1. 大纲必须有固定目录、固定对象类型、固定 ID 和固定字段。
2. 人类可读文本可以存在，但不能替代关键结构化字段。
3. 任何章节必须能够追溯到卷、弧、线、目标、冲突和义务。
4. 未注册实体可以作为候选，不能直接进入权威状态。
5. 大纲允许后续变更，但所有变更必须进入版本和影响分析。

## 3. 00-manifest.yaml

```yaml
schema_version: outline.v1
book_id: book_demo
title: 示例书
language: zh-CN
genre_profile: general_serial
status: draft | approved | frozen
planned_words: 1000000
planned_chapters: 500
chapter_word_range: [2500, 4500]
point_of_view: configurable
tense: configurable
canon_policy: strict | guided | emergent_with_reconcile
created_at: 2026-09-29
last_modified_at: 2026-09-29
approval:
  owner: author
  approved_at: null
```

必填：`schema_version`、`book_id`、`title`、`language`、`planned_chapters`、`canon_policy`。

## 4. 01-premise.md

允许 Markdown，但必须包含固定标题：

```markdown
# 一句话 premise

# 核心冲突

# 主角不可替代性

# 读者承诺

# 终局方向

# 禁止事项
```

这些栏目不是文学作文，而是编译器需要的约束源。

## 5. 结构对象规范

### 5.1 Character

```yaml
id: char_lin_yun
name: 凌云
role: protagonist
initial_state:
  age: 19
  location: place_border_town
  status: unknown_disciple
motives:
  primary: 找回师父遗骨
  secondary: 证明清白
fears:
  - 发现自己一直被利用
capabilities:
  - sword_basic
constraints:
  - cannot_read_ancient_script
arc_refs: [arc_main_01]
voice_profile: voice_lin_yun
```

至少必须有：

- 稳定 ID
- 初始状态
- 至少一个动机
- 至少一个限制
- 至少一个能力或资源边界
- 所属弧线

### 5.2 Faction

必须有：

- 目标
- 资源
- 层级/位阶
- 对外关系
- 内部冲突
- 已知信息边界

### 5.3 Place

必须有：

- 位置/可达性
- 环境限制
- 所属势力
- 可发生动作
- 首次出现章节

### 5.4 Item

必须有：

- 当前持有者
- 来源
- 能力/限制
- 转移规则
- 是否为伏笔载体

### 5.5 Thread

```yaml
id: thread_master_betrayal
type: mystery
priority: high
promise: 师父之死并非表面原因
start_chapter: 1
planned_reveal_window: [80, 140]
related_characters: [char_lin_yun, char_master]
related_obligations: [ob_master_betrayal]
status: open
```

## 6. 09-threads.yaml：剧情线规范

每条剧情线必须写清：

```yaml
id: thread_main_revenge
kind: main | subplot | relationship | mystery | commerce
owner: char_lin_yun
start_condition: ...
progress_metric: ...
turning_points:
  - id: tp_01
    target_chapter: 30
    action: ...
    irreversible_change: ...
resolution_condition: ...
forbidden_resolution: ...
```

禁止只写“主角成长”“调查真相”“感情升温”这种不可执行描述。

必须转换成：

- 谁做什么
- 在什么前置条件下
- 改变什么状态
- 产生什么代价
- 何时需要推进
- 什么结果算完成

---

## 7. 10-obligations.yaml：未来义务规范

```yaml
- id: ob_master_betrayal
  kind: foreshadowing
  source_thread: thread_master_betrayal
  planted_chapter: 3
  expected_window: [80, 140]
  weight: 0.9
  allowed_resolution:
    - fulfilled
    - subverted
    - deferred
  reader_visibility: concealed
  character_visibility:
    char_lin_yun: unknown
    char_master: confirmed
  evidence_requirement:
    min_clues: 2
    payoff_requires: [event_master_truth_revealed]
```

每条未来义务必须说明：

- 谁欠了什么
- 对谁欠
- 何时开始
- 何时应触发
- 可以如何兑现/反转/延期
- 什么证据才算完成

## 8. 11-arcs.yaml 与 12-chapter-map.yaml

### Arc

```yaml
id: arc_main_01
volume: vol_01
range: [1, 50]
entry_state: ...
exit_state: ...
core_question: ...
required_turns: [...]
obligations_created: [...]
obligations_resolved: [...]
```

### Chapter

```yaml
id: ch_001
volume: vol_01
arc: arc_main_01
purpose: introduce_conflict
pov: char_lin_yun
location: place_border_town
time:
  start: story:0019-04-01T08:00
  end: story:0019-04-01T12:00
intent:
  required_events: [event_first_attack]
  required_changes: [char_lin_yun.status=exposed]
  required_hook: hook_escape_or_truth
  forbidden: [new_unregistered_faction]
beats:
  - id: beat_001_01
    kind: action
    target_words: [500, 900]
    complexity: medium
```

章节必须至少有：

- 目的
- POV
- 时间和地点
- 必须发生的事件
- 必须改变的状态
- 章末钩子
- 禁止事项
- beat 列表

## 9. 13-style.yaml

文风不是一句“写得精彩”，而是可操作配置：

```yaml
narration:
  distance: close
  rhythm: variable
  description_density: medium
dialogue:
  tag_policy: restrained
  character_voice_required: true
pacing:
  action_ratio: configurable
  reflection_ratio: configurable
forbidden_patterns:
  - generic_summary_ending
  - repeated_empty_emotion
  - unearned_revelation
platform_constraints:
  target: configurable
  ai_style_check: enabled
```

文学品味不在这里被完全形式化，但可测原则必须写在这里。

## 10. 大纲的三种进入路径

### 路径 A：完整结构化大纲

作者直接提供完整 Outline Package。

状态：

```text
draft → validated → approved → compiled
```

### 路径 B：半结构化大纲

作者提供固定模板下的 Markdown/表格，由 Architect Agent 补全结构字段。

要求：

- Agent 只能补候选值。
- 缺失字段进入 `needs_human_input`。
- 不允许 Agent 自行冻结世界事实。

### 路径 C：旧项目迁移

对 NOVEL、antigravity-novel、v5、gallant 等旧数据执行：

```text
import → normalize → candidate entities → collision report → human confirm → compile
```

迁移绝不直接覆盖新项目权威状态。

## 11. 编译流程

```text
1. 读取 manifest
2. 校验文件存在与 schema_version
3. 收集所有对象和 ID
4. 检查 ID 冲突、别名冲突、循环引用
5. 编译时间线
6. 编译剧情线和章节图
7. 编译未来义务
8. 编译初始角色/读者知识
9. 生成 intent ledger
10. 生成 production manifest
11. 生成初始事件
12. 输出 compile report
```

编译器输出：

```text
workspace/<book>/compiled/
├── objects.json
├── initial-state.json
├── obligations.json
├── timeline.json
├── intent-ledger.json
├── production-manifest.yaml
└── compile-report.md
```

## 12. 编译失败类型

```text
OUTLINE_MISSING_FILE
OUTLINE_SCHEMA_ERROR
DUPLICATE_ID
ALIAS_COLLISION
UNKNOWN_REFERENCE
CIRCULAR_DEPENDENCY
TIME_CONTRADICTION
OBLIGATION_WITHOUT_RESOLUTION
CHAPTER_WITHOUT_PURPOSE
CHAPTER_WITHOUT_HOOK
UNBOUNDED_CHARACTER
FORBIDDEN_FREE_TEXT_CANON
```

任何一项 hard failure 都不得生成 `status: compiled`。

## 13. 大纲修改规则

修改已编译大纲时必须生成：

```yaml
change_id: change_0007
reason: ...
affected_objects: [...]
affected_chapters: [...]
affected_obligations: [...]
blast_radius: ...
requires_replan: true
requires_human_approval: true
```

变更分级：

```text
P0  改主角身份、终局、世界硬规则、已发布事实
P1  改卷级转折、核心伏笔、角色弧线
P2  改未生产章节细节、beat、节奏
P3  改文风、措辞、非权威备注
```

P0/P1 必须人工确认；P2 可由 Planner 重新编译；P3 可自动处理但必须保留版本。

---

## 14. 大纲规格验收

一份有效大纲必须：

1. 通过完整 schema 校验。
2. 所有引用 ID 存在。
3. 所有主要角色有动机和限制。
4. 所有主线有入口、推进、转折和出口。
5. 所有未来义务有预期窗口和解决方式。
6. 所有计划章节有目的、状态变化和钩子。
7. 时间线可以被编译。
8. 可以生成第一份 ContextPack。
9. 可以生成第一章的 production task。
10. 故意删除一个字段时被确定性拦截。
