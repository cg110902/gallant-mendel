# M6.6 三章连续提交与恢复 Smoke 补充冻结决策
## Contiguous Authority, Recovery, and No-Silent-Loss v1

- 状态：已接受
- 日期：2026-09-30
- 前置：M6.5 PASS（22/22）

## 1. 评估结论

M4.1 的 readiness 实现只返回首章，无法执行真实连续生产。M6.6 正式将其升级为按 EventLog 中 `chapter.committed` 选择大纲内首个未提交章节；Run 目录或 chapter 文件均不得替代 authority 判断。除此以外不改变 M5 gate、advisory 或 threshold 协议。

三章 smoke 是恢复与数量守恒检查，不是三章文学质量证明，更不是 30 章、并发或生产可靠性结论。

## 2. 冻结执行链

`ch_001` 至 `ch_003` 必须逐章执行：

```text
plan → context → writer/review → extract → reconcile → hard audit
→ semantic/style → warning advisory → human gate → authority commit
```

每章 request 的 `authority_head` 必须等于前章 `commit_head`。每个 commit report 的全部 event ID 必须在 EventLog 中存在，chapter bytes/hash、status/commit hash 与 advisory hash 必须一致。

## 3. CED 与 advisory 隔离

M6.6 CED 只报告一个固定连续窗口 `ch_001..ch_003`：

```text
CED = hard consistency error count / 3
```

Advisory warning 单独计数并明确排除于 CED；不得把 warning 升为 hard error，也不得因 smoke 结果修改 M6.5 challenge 的 9 个 FN。

## 4. Snapshot 与中断恢复

在第二章发布后创建 verified snapshot，必须携带继续生产所需 outline、compiled、runs、production 与 chapters artifacts。恢复到新的、空目标后执行第三章，验证恢复点 EventLog/SQLite 与 artifact receipts 均可继续使用。

第二章提交额外注入一次“commit intent 已落盘、EventLog 只存在 deterministic 前缀”的中断。重试必须验证前缀 bytes，只追加缺失后缀，并最终发布 chapter、projection、report/status；不允许删除或重写已经追加的 authority。

## 5. Silent-data-loss 检查

报告至少检查：

- authority 初始数量 + 三章 commit event 数量 = 最终数量；
- 三个 parent/head 连续；
- 三个 `chapter.committed` 与三个 chapter 文件守恒；
- 三章新增 fact 在 temporal query 与 projection 中均存在；
- projection head 等于 EventLog head；
- 三个 Run 的 commit receipt 均存在；
- snapshot 在第二章 head 创建，restore 后第三章可提交。

任一检查失败时 `silent_data_loss=true` 且 smoke 不通过。

## 6. 诚实边界与后续

- 保留 challenge transfer：TP=9、FP=0、TN=18、FN=9；
- threshold 继续 warning-only，不自动升级 hard gate；
- 本阶段不覆盖模型 Judge、自然语言 PersonaDrift、同义 trope/filler、30 章、并发、吞吐或性能；
- 三章 CED=0 只表示该固定控制样本窗口未产生 hard consistency error。

M6.6 通过后，下一步只能先评估 M6.7 扩展运行边界；不得由三章 smoke 直接宣称生产可靠。
