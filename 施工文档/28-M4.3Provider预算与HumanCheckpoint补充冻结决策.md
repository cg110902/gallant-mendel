# M4.3 Provider、预算与 Human Checkpoint 补充冻结决策
## Bounded Provider and Human Gate v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M4.2 PASS（13/13）

## 1. 评估结论

M4.3 完成 M4 Production Harness：接入一个 OpenAI-compatible HTTPS provider adapter，冻结输入/输出预算、超时、凭据隔离和人工检查点。测试使用注入 transport，验收不访问公网、不要求 API key。

真实 provider 是显式 opt-in；默认继续使用 offline adapter。Provider 成功只产生候选正文，不表示质量合格或权威提交。

## 2. Provider 边界

- provider 仍只接收 ContextPack 与冻结 Writer Skill；不得读取项目文件、EventLog、SQLite、环境中的其他故事资料或聊天历史；
- endpoint 必须为 HTTPS；仅测试注入 transport 可绕开真实网络；禁止 URL 内凭据和 query/fragment；
- API key 只从 `NOVEL_PROVIDER_API_KEY` 读取，绝不写入 request/result/stdout/stderr、状态、异常正文或证据；
- 配置来自 `NOVEL_PROVIDER_URL`、`NOVEL_PROVIDER_MODEL` 和显式预算环境变量；缺失即在调用前失败；
- 不执行任意 shell，不自动 fallback 到其他 provider，不自动重试收费请求；恢复必须显式 `run resume` 并创建新 attempt。

## 3. 预算、超时与响应

调用前校验 ContextPack 字符数不超过其中的 `hard_limit_chars`。冻结默认上限：输出 12,000 字符、6,000 output tokens、总 token 32,000、超时 120 秒。Provider usage 超限或正文为空/超限均失败并保留 attempt 证据。

HTTP 响应只接受 UTF-8 JSON，候选正文取 `choices[0].message.content`。HTTP 错误只记录状态和安全类别，不保存响应体或 Authorization header。

## 4. Human checkpoint

状态扩展：

```text
draft_ready → human_review
human_review → extraction_ready   (approve)
human_review → needs_rework       (rework)
needs_rework → writer_running     (显式 resume，新 attempt)
```

`run review` 冻结当前 `prose.md` hash；`run decide` 要求非空 actor，生成不可覆盖的 review decision，绑定 context/prose hash。等待期间正文改变会使决定失败。approve 仅允许 M5 Extractor 接手，不执行抽取；rework 不修改正文。

## 5. CLI

```bash
python studio.py run start ... --runtime openai-compatible
python studio.py run review (--book ID | --path PATH) --run run_<hash>
python studio.py run decide (--book ID | --path PATH) --run run_<hash> --decision approve|rework --actor ID [--note TEXT]
```

## 6. 明确排除

不宣称 OS sandbox；不持久化凭据；不做自动 provider retry/fallback；不实现 claims 抽取、审计、章节发布或 EventLog commit。M4.3 通过后下一阶段只能评估 M5.1 candidate extraction/evidence binding。
