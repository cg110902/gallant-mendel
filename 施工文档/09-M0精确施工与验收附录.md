# M0 精确施工与验收附录
## 工程宪法、最小 CLI、Doctor 与故意损坏 Fixture v1.0

> 本文件把 M0 从“任务列表”细化为新会话可以直接执行的工程合同。

---

## 1. M0 的目标

M0 只证明工程具有一个可执行、可诊断、可拒错的基础，不证明小说生产功能已经存在。

M0 完成后，系统必须能够：

1. 确认 Python 版本和工程布局；
2. 在无 API Key、无第三方依赖时运行；
3. 对缺文件、坏配置、缺权限和错误 fixture 给出确定性失败；
4. 输出稳定的版本、帮助和诊断结果；
5. 让下一会话知道从哪里继续；
6. 为 M1 提供不再反复修改的目录、退出码和基础命令。

---

## 2. M0 明确不做

以下功能不得在 M0 实现：

- 事件追加和事件重放；
- Object / Facet / Relation 业务逻辑；
- SQLite 状态投影；
- Outline Package 编译；
- 模型调用、API 客户端或 Agent 调度；
- ContextPack 和 ArtifactBundle 的生产；
- 正文生成、抽取、审计和章节提交；
- Web 服务、向量库、图数据库和常驻后台进程。

M0 只建立骨架和拒错能力。

## 5. CLI 最小合同

入口：

```bash
python studio.py <command> [options]
```

首期只实现四个命令：

```text
version
help
 doctor
init
```

`init` 在 M0 只做最小目录初始化，不编译大纲、不创建业务事件。

### 5.1 `version`

```bash
python studio.py version
python studio.py version --json
```

要求：

- 成功返回退出码 `0`；
- 普通输出包含项目名、版本号、Python 要求和 `m0`/开发状态；
- `--json` 输出一个可解析 JSON 对象；
- 不访问网络、不读取 API Key、不写业务状态。

建议的 JSON 字段：

```json
{
  "project": "novel-production-os",
  "version": "0.1.0-dev",
  "phase": "M0",
  "python_min": "3.11",
  "api_required": false
}
```

### 5.2 `help`

```bash
python studio.py help
python studio.py --help
python studio.py help doctor
```

要求：

- 返回退出码 `0`；
- 输出当前支持的命令、示例和帮助入口；
- 不把尚未实现的 M1–M8 命令伪装成可用；
- 未知命令返回退出码 `1`，并把错误写到 stderr。

### 5.3 `doctor`

```bash
python studio.py doctor
python studio.py doctor --no-api-key
python studio.py doctor --json
python studio.py doctor --no-api-key --json
```

Doctor 首期检查：

| 检查项 | 失败时退出码 | 说明 |
|---|---:|---|
| Python >= 3.11 | 5 | 环境错误 |
| 当前工作目录符合工程根目录 | 1 | 输入/布局错误 |
| `AGENTS.md` 存在 | 1 | 工程布局错误 |
| 基础目录存在 | 1 | 工程布局错误 |
| 版本文件可读取 | 2 | 格式错误 |
| 临时目录可写 | 5 | 权限/环境错误 |
| 标准库 JSON 可用 | 5 | 环境错误 |
| API Key 不存在 | 不失败 | 核心路径不要求 API Key |
| `--no-api-key` 路径 | 不失败 | 必须明确显示 no-api-key-ready |

Doctor 不得把“用户没有 API Key”判为失败。

`--json` 至少包含：

```json
{
  "ok": true,
  "phase": "M0",
  "checks": [
    {
      "id": "python_version",
      "status": "pass",
      "exit_code_if_failed": 5,
      "message": "..."
    }
  ],
  "api_key_required": false
}
```

### 5.4 `init`

```bash
python studio.py init --path workspace/_fixture/initialized
python studio.py init --path workspace/_fixture/initialized --force
```

M0 的 `init` 只允许：

- 创建规定的空目录；
- 写入最小版本/manifest 元数据；
- 不覆盖已有文件，除非明确使用 `--force`；
- 不创建 `events.jsonl`、`state.db` 或正文；
- 成功退出 `0`，目标已存在且无 `--force` 时退出 `1`。

如果实现者认为 `init` 需要更复杂的书籍协议，必须留到 M2，不得在 M0 扩展。

## 6. 退出码合同

全局退出码固定如下：

```text
0  SUCCESS                  成功
1  INPUT_OR_CONFIG_ERROR    参数、路径或配置错误
2  SCHEMA_FORMAT_ERROR      JSON/schema/结构格式错误
3  HARD_VIOLATION           硬一致性违规
4  HUMAN_GATE               需要人工审批或存在未决冲突
5  ENVIRONMENT_ERROR        Python、权限、依赖或运行环境错误
6  REPLAY_PROJECTION_ERROR  事件重放或状态投影错误
7  RESOURCE_GUARD           资源、预算或并发保护触发
```

M0 必须覆盖 `0、1、2、5`；`3、4、6、7` 先在 `exit-codes.md` 固定，但业务触发留给后续里程碑。

规则：

- 退出码写入命令日志；
- 正常结果写 stdout；错误和诊断写 stderr，`--json` 结果仍可写 stdout；
- 不用异常 traceback 代替用户可执行错误；
- 未知命令不能返回 `0`；
- 错误不得静默创建或修改权威业务状态。

## 7. Fixture 验收矩阵

M0 至少包含以下测试：

| Fixture/情形 | 命令 | 预期 |
|---|---|---|
| valid 工程布局 | `doctor --no-api-key` | 退出 `0` |
| 缺少 manifest | `doctor` 或验证脚本 | 退出 `1` 或 `2`，具体取决于缺失层级并写清原因 |
| 非法 JSON | 版本/fixture 验证 | 退出 `2` |
| 缺少必填字段 | fixture 验证 | 退出 `2` |
| 目标目录不可写 | doctor 权限探针 | 退出 `5`，或明确 `SKIP` 并记录平台原因 |
| 无 API Key | `doctor --no-api-key` | 退出 `0` |
| 未知命令 | `studio.py not-a-command` | 退出 `1` |
| 重复初始化 | `init --path existing` | 无 `--force` 退出 `1` |

测试不得依赖真实云服务、真实模型或用户环境中的密钥。

## 8. M0 测试文件

`tests/test_m0_cli.py` 至少覆盖：

1. version 返回 0；
2. version JSON 可解析；
3. help 返回 0；
4. unknown command 返回 1；
5. doctor no-api-key 返回 0；
6. doctor JSON 包含 checks；
7. init 创建目录；
8. init 默认不覆盖；
9. 非法 fixture 返回 2；
10. 退出码枚举与 `exit-codes.md` 一致。

`scripts/verify_m0.py` 是面向 Agent/人工的黑盒验收脚本，必须通过子进程调用 `studio.py`，不能只 import 内部函数后宣布通过。
