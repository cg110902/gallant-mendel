# M7.2 四 IDE 兼容性 Surrogate 矩阵补充冻结决策

- 状态：已接受
- 日期：2026-09-30
- 前置：M7.1 PASS

## 决策
在无法从自动化沙箱启动四家真实 IDE 的前提下，兼容性验收必须拆为两层：可自动复验的 portable-core surrogate，以及用户在真实 IDE 中执行的 live attestation。不得用前者冒充后者。

四个平台各映射同一组 10 项能力：skill discovery、workspace init、ContextPack、Writer candidate、Writer authority guard、hard error detection、hard error blocks commit、projection rebuild、interrupt/resume、no-API-key doctor。每项运行真实 unittest/CLI 路径，而不是只检查文件存在。

报告固定 `execution_mode=portable_core_surrogate`、`vendor_runtime_executed=false`、`live_attestation_required=true`。四平台可共享 portable core 结果，因为 thin adapter 不拥有业务逻辑；但真实 Antigravity/Claude/Cursor/Codex 的 UI、hook 和 sandbox 效果必须分别人工签署。

## 诚实边界
通过只证明 40 个 adapter-to-core capability mappings 的底层确定性能力通过，不证明厂商 IDE 已启动。下一步先准备并执行 Antigravity live acceptance；用户打开 Antigravity 后按证据清单运行，不重写 authority。
