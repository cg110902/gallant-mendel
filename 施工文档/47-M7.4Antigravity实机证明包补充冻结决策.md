# M7.4 Antigravity 实机证明包补充冻结决策

- 状态：已接受（工具链）；真实实机结论仍 PENDING
- 日期：2026-09-30
- 前置：M7.3 PASS

## 决策

在用户打开 Antigravity 前，先冻结 live attestation 的输入、证据绑定与验收边界，避免事后以聊天结论冒充证据。

1. `studio.py ide template` 只生成 pending 模板，绝不写 `vendor_runtime_executed=true`。
2. 固定 11 项：六个 `/novel-*` workflow，以及 doctor、compatibility matrix、branch create、rollback、repeat export。
3. `studio.py ide attest` 只有在 11 项全部为 pass、每项至少绑定一份 bundle 内普通文件、所有 SHA-256 一致、操作者声明和带时区执行时间完整时才产生 accepted bundle。
4. final bundle 才允许 `vendor_runtime_executed=true`；该值表达操作者签署的实机执行，不表达自动化工具自己启动过 IDE。
5. evidence 禁止绝对路径、目录逃逸和直接 symlink；surrogate 报告保持原样，不得反写为真实 IDE evidence。
6. fail/pending/missing/tampered evidence 必须拒绝，不得生成 accepted bundle。

## 诚实边界

operator attestation 是可哈希、可复验的工程签署，不是 PKI 数字签名，也不证明截图内容语义真实。工具链 PASS 与 Antigravity live acceptance PASS 是两个不同状态；在用户执行前，项目状态必须继续标为 PENDING。
