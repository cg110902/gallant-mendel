# M5.5 Chapter Commit Transaction 补充冻结决策
## Recoverable Authority Commit v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M5.4 PASS（15/15）

## 1. 提交资格

只有状态为 `audit_approved`、完整 hash chain 未漂移、authority head 与 compile ID 仍匹配计划的 Run 可以提交。命令要求稳定 actor ID：

```bash
python studio.py commit chapter (--book ID | --path PATH) --run RUN_ID --actor ACTOR [--json]
```

## 2. 事件批次

提交生成并冻结 `commit-intent.json`，其中包含 deterministic event IDs、单一 recorded timestamp、批准正文 hash 和完整事件批次：

1. `audit.completed`；
2. 每个非 `no_change` candidate fact 的 `fact.asserted`；
3. `chapter.committed`；
4. `reality.observed`；
5. `state.reconciled`。

Reality 的 missing/extras 必须显式绑定本批次 `audit.completed`，不得静默丢弃。Fact evidence 转换为 chapter exact-span Evidence；候选 ID 与 authority fact ID 均确定性派生。

## 3. 可恢复事务边界

跨 JSONL、chapter 文件和 SQLite 无法伪装成单文件 ACID。冻结顺序：

```text
validate all → persist commit intent → append authoritative batch
→ atomically publish chapter → update derived projection → publish commit report/status
```

EventLog batch先全量验证并在单锁/单 fsync 下追加。若中断后存在完整 deterministic 前缀，重试验证 bytes 后只追加剩余后缀；若出现截断 JSONL、非前缀或 bytes 不同，停止并要求恢复，不自动截断权威日志。事件已追加而 chapter/projection 未完成时，重试负责补齐派生步骤。

## 4. 状态

```text
audit_approved → commit_prepared → authority_committed → published
```

`published` 要求：全部事件存在且一致、`chapters/<chapter_id>.md` bytes/hash 一致、projection head 等于 commit head、commit report 已发布。同一 Run 重试幂等；不同 bytes 冲突返回完整性错误。

## 5. 安全边界

- actor 必须匹配 core actor ID；Writer/Extractor/Auditor 不得成为 authority actor；
- 提交前后禁止计划之外的 authority head 漂移；
- chapter 文件只能来自 approved prose 原始 bytes；
- 不自动修复或覆盖已有不同 chapter；
- `state.db` 始终是可重建派生层，EventLog 才是权威。

## 6. 后续

M5.5 通过后 M5 主链完成；下一步只能进行 M5 总回归与单章端到端验收，再进入 M6 mutation/calibration，不直接宣称生产可靠性。
