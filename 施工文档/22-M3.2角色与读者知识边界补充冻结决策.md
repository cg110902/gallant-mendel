# M3.2 角色与读者知识边界补充冻结决策
## Knowledge Boundary Query v1

- 状态：已接受
- 日期：2026-09-29
- 前置：M3.1 PASS
- 影响范围：知识事件载荷、角色/读者可见性、as-of 知识差集只读查询

## 1. 评估结论与阶段边界

M3.2 的首个可验收切片只实现“谁在何时知道哪个已登记 Fact”的权威读取：

- 角色知识与读者知识使用同一事件折叠机制，但状态词表和来源约束不同；
- 缺少知识边表示 `unknown`，不持久化 `unknown` 边；
- 知识成立不等于 Fact 为真，Fact 为真也不等于 holder 已知；
- 复用 M3.1 的 recorded/event/chapter cutoff 和可选 world valid-at；
- 输出角色、读者、事实真值三个集合的确定性差集。

本切片不实现 Future Obligation、Intent/Reality、张力分数、impact、ContextPack、生产 Agent 或正文生成。

## 2. 权威与键

知识权威来自 selected EventLog lineage 中的 `knowledge.granted` / `knowledge.retracted`，键为：

```text
(holder_id, knowledge_id)
```

- `knowledge_id` 必须引用 grant 时已经存在的 Fact；
- 普通 holder 必须是 grant 时已经存在且类型为 `character` 的 Object；
- `_reader` 是唯一保留的虚拟 holder，不要求 Object 记录；
- 同一键已有 active grant 时禁止再次 grant，必须先 retract；
- retract 必须命中 active edge；retract 后可再次 grant；
- branch 只继承 lineage 祖先，不读取其他分支知识。

## 3. Grant v1 载荷

```json
{
  "knowledge": {
    "holder_id": "char_lin_yun",
    "knowledge_id": "fact_master_betrayal",
    "state": "suspected",
    "confidence": 0.7,
    "source_refs": ["chapter:ch_042#p8"],
    "source_event_id": "event_<32hex>"
  },
  "evidence": []
}
```

角色状态词表：`suspected | believed | confirmed | false_belief`。
读者状态词表：`clue | suspected | confirmed | misled`。

- `confidence` 是 `[0,1]` 的有限数字，布尔值非法；
- `source_refs` 为非空、去重字符串数组；
- `source_event_id` 可为 `null`，但仅角色的 outline 初始知识允许为 null，且 source_ref 必须以 `outline:` 开头；
- 非 null source event 必须是 lineage 中更早的 `scene.committed` 或 `chapter.committed`；
- `_reader` 禁止 outline/Bible 来源，必须引用更早的 `chapter.committed`，从而保证读者知识只能来自已发布章节；
- carrying event 的 `story_seq` 是获得知识的 narrative sequence，`recorded_at` 仍只表示系统记录时间。

## 4. Retraction v1 载荷

```json
{
  "holder_id": "char_lin_yun",
  "knowledge_id": "fact_master_betrayal",
  "reason": "memory_corrected",
  "source_refs": ["chapter:ch_057#p19"],
  "evidence": []
}
```

retract 清除 active edge。历史 grant 不删除，event cutoff 仍可重建撤回前知识。

## 5. 查询与集合语义

命令：

```bash
python studio.py knowledge diff --book book_demo --holder char_lin_yun --as-of ch_010
```

可选参数与 M3.1 一致：`--valid-at`、`--branch`、`--json`。

记：

- `T`：M3.1 cutoff/valid-at 下 status 为 `asserted` 的 Fact ID；
- `C`：目标角色 active knowledge edge 的 Fact ID；
- `R`：`_reader` active knowledge edge 的 Fact ID。

稳定输出：

```text
reader_only       = R - C
holder_only       = C - R
shared            = R ∩ C
hidden_truth      = T - (R ∪ C)
known_false_or_disputed = (R ∪ C) - T
```

知识集合包含 `suspected`、`clue`、`misled` 等边；状态保留在 edge 中，集合差不宣称其都为 confirmed。张力评分留待后续里程碑。

## 6. 输出、只读性与错误

成功 schema 为 `knowledge-diff.v1`，包含 branch、cutoff、valid_at、holder、角色/读者 edges、五个稳定排序集合和 canonical logical hash，不含墙钟时间。

查询严格只读，不创建 SQLite、临时数据库、缓存或知识投影。

- 非法参数：退出 `1`；
- chapter story sequence 非单调：退出 `3`；
- EventLog、知识载荷、引用或状态机完整性错误：退出 `6`。
